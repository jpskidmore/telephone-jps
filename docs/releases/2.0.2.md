# jps Telephone 2.0.2 (build 153)

Version 2.0.2 fixes the application crash that could occur when a recorded call
ended and its call window was released.

## Root cause

The call controller tried to create a weak reference to itself after
Objective-C deallocation had begun. macOS correctly aborted in
`objc_initWeak`. Repeated hang-up and disconnect callbacks could also request
recording finalization more than once while stereo encoding was still running.

## Fix

Recording finalization is now idempotent, and call-controller teardown uses a
cleanup callback that does not reference the deallocating controller. Access to
a user-selected recordings folder remains active until asynchronous encoding
has finished.

The release includes the corrected Apple-silicon app, complete source, a
verification report, and SHA-256 checksums.

## Verification

- The recording hardening harness and vendored-library security baseline pass.
- The signed Release app passes code-signing, entitlement, version, build, and

No live telephone call was placed as part of the automated release checks.
