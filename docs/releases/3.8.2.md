# jps Telephone 3.8.2 (169)

Moves SIP credentials to the stable `uk.jpsit.telephone.sip:<exact registrar>` Keychain service with the label **jps Telephone — SIP account**. Canonical entries are checked first; only absence permits legacy fallback. Authorised migration preserves the original file Keychain and access list, verifies the new copy and retains legacy items for rollback.

Explicit password saves update the compatibility copy and verify both the saved canonical copy and the credential selected by normal lookup. A different or unreadable entry earlier in the Keychain search list now produces a partial-save error instead of a false success. Account settings are not committed after an unverified save. Other Keychain entries are not automatically overwritten or removed to resolve a conflict.

Keychain Access labels, actual access-control enforcement, macOS prompt wording/counts, multiple-account upgrade/registration and rollback remain unverified. Additional permission prompts are possible; the existing signing policy has not changed. Legacy “blue icon v4” service fields intentionally remain as rollback copies. Issue #77 stays open for this acceptance; #62 was closed when the owner stopped its earlier practical-testing round.

Apple silicon; macOS 15.6 or later. Ad-hoc signed and unnotarised, consistent with previous releases. Built and packaged locally; no cloud workflow, local installation, production-profile launch or live credential/provider test is part of this release. Fresh completed release checks are recorded in BUILD-VERIFICATION.md; hashes are in SHA256SUMS.txt. All previous releases remain unchanged.
